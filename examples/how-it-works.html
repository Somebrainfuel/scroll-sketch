Hand-drawn charts that draw themselves as you scroll

Ben's Ramp story looks like someone sketched it on a notepad, and every chart builds up as you read. It's less magic than it looks. It's five small, plain web tricks used together.

I took apart his live page. It's a single HTML page, a free library called Rough.js for the sketchy lines, the Shantell Sans handwriting font, and one small script per chart. The email version uses screen-recorded GIFs of the same charts, because emails can't run code.

  • 1A pinned stage. A very tall section with a chart inside that sticks to the screen while you scroll past it.
  • 2One number: scroll progress. How far through the section you are, from 0 to 1.
  • 3A script. Slices of that number mean "draw the line", "add the dots", "move these up".
  • 4A sketchy pen. Rough.js draws normal SVG lines and circles with a wobble, like a marker.
  • 5Reveal tricks. Clipping a line so it grows, fading things in, sliding dots to new spots.

Every part of that came from one number between 0 and 1. Here's each ingredient, with the code that does it.

1 · Pin the chart

The section is 4–6 screens tall. Inside it, a box exactly one screen tall uses position: sticky, so it stays put while the rest of the section scrolls past. Ben's sections are 400vh to 620vh tall. Taller means slower and calmer.

<!-- HTML -->
<section class="scrolly" id="story">
  <div class="pin"><div class="host"></div></div>
</section>

/* CSS */
.scrolly { position: relative; height: 460vh; }
.pin { position: sticky; top: 0; height: 100vh;
       display: flex; flex-direction: column; justify-content: center; }

2 · Turn scrolling into one number

On every scroll, measure how far the section's top has moved up past the screen, and divide by how far it can move. You get p: 0 when the chart first pins, 1 when it lets go.

const clamp = (v, a = 0, b = 1) => Math.max(a, Math.min(b, v));

function progress(section) {
  const r = section.getBoundingClientRect();
  return clamp(-r.top / (r.height - innerHeight));
}

// redraw at most once per frame, however fast people scroll
let raf = 0;
addEventListener('scroll', () => {
  if (!raf) raf = requestAnimationFrame(() => { raf = 0; update(); });
}, { passive: true });

3 · Write the script as slices of p

This is where the storytelling happens. A tiny helper, seg(p, start, end), turns one slice of the scroll into its own 0→1 for a single step. The blank gaps in the bar above are deliberate pauses, so the reader can take in each state before the next change.

const seg = (p, a, b) => clamp((p - a) / (b - a));

function update() {
  const p = progress(section);
  S.axes  = seg(p, 0.00, 0.10);   // the line grows
  S.dots  = Math.round(seg(p, 0.10, 0.35) * ITEMS.length); // dots appear one by one
  S.rise  = seg(p, 0.40, 0.75);   // pause, then the boring ones climb
  S.note  = seg(p, 0.82, 1.00);   // the circle scribbles itself
  apply();                        // push S onto the drawing
}

Keep two jobs apart. draw() builds the whole chart once (and again when the width changes). apply() only moves and toggles what's already there, so scrolling stays smooth.

4 · Draw with a sketchy pen

Rough.js has the same shapes as plain SVG (line, rectangle, circle, ellipse, path), but with a hand-drawn wobble. Play with the settings below. The seed matters: with a fixed seed, a shape wobbles the same way every time it's redrawn. Without one, the chart would jitter on every resize.

Getting it into your newsletter

  
Email apps strip out scripts, so do what Ben did: put the live version on a web page, and in the email use a GIF of each chart that links to it.

  
    
    
  1. Host the page. On WordPress, a page with one Custom HTML block holding the whole file works. A blank page template is best, so the theme's sidebar doesn't squeeze the chart.
    2. 
    
  2. Record each chart. On a Mac, press ⌘ Shift 5, choose "Record Selected Portion", draw a box around the chart, and scroll through it slowly.
    3. 
    
  3. Make the GIF. Ben's are 1100px wide. This makes a sharp, small file from the recording:

    ffmpeg -i chart.mov -vf "fps=15,scale=1100:-1:flags=lanczos,split[a][b];[a]palettegen[p];[b][p]paletteuse" -loop 0 chart.gif
    
      Try to keep each file under about 3 MB so it loads quickly in Gmail and Outlook. Trim slow stretches or drop to fps=12 if it's too big.
    4. 
    
  4. Link the image to the page, and add a line like Ben's: "it's just not the same in the email".

Make your own with Claude

  
You don't need to hand-write any of this. Sketch the chart on paper first (Ben's code mentions "positions from Ben's sketch"), then give Claude a brief like this one, filled in with your own story:

  

    

Build a single self-contained HTML page with one scroll-driven, hand-drawn chart.

Style
- Rough.js (from cdn.jsdelivr.net/npm/roughjs@4.6.6/bundled/rough.js) for all lines and shapes, each shape with a fixed seed so it never jitters on resize.
- "Shantell Sans" for chart text and "Inter" for body text, from Google Fonts.
- Mostly ink on white, one accent colour for the thing that matters, a marker highlight for key words. Works in dark mode too.

Mechanics
- The chart sits in a section 450vh tall, pinned with position: sticky.
- Work out scroll progress p (0 to 1) through the section, and use seg(p, start, end) slices to drive each step.
- draw() builds the SVG on load and on resize; apply() only moves and toggles things on scroll, using requestAnimationFrame.
- Leave short pauses between steps.

The story (my sketch)
- X axis: [what goes across]. Y axis: [what goes up].
- Step 1: draw the axes and [a reference line, e.g. "line of expected payoff"].
- Step 2: plot these items one by one: [name, x 0–1, y 0–1] …
- Step 3: [what moves or changes, and where it ends up].
- Step 4: circle [the point] with a handwritten note: "[your punchline]".

Also add a short caption under the chart that changes with each step, and an aria-label that describes the whole chart.
